# Pharmacovigilance CE course

Live at https://mednovalife.com/pharmacovigilance-ce-course

## How it fits together

| Part | Where |
| --- | --- |
| Course as authored (modules, quizzes, certificate design) | `tools/pv-ce-course/source/Pharmacovigilance_CE_Course.html` |
| Build script (source → site page + answer key) | `tools/pv-ce-course/build.py` |
| Site page (generated, don't edit by hand) | `frontend/pharmacovigilance-ce-course.html` |
| Answer key the server grades against (generated) | `frontend/api/course-key.json` |
| Module content and quizzes, sent only to learners with access (generated) | `frontend/api/course-content.json` |
| API: sign-in, device codes, grading, certificates, register | `frontend/api/course.js` |
| Routes | `frontend/vercel.json` (`/pharmacovigilance-ce-course`, `/api/course`) |
| Database | Supabase project `mednova-website`, table `public.course_learners` |
| Signatory's scanned signature (optional) | `frontend/public/images/course/signature.png` |

The Vercel project's root directory is `frontend/`, so the root `vercel.json` is not used.

## Changing the course content

1. Replace or edit `source/Pharmacovigilance_CE_Course.html` (for example, a new export of the course).
2. From the repository root run:

   ```
   python tools/pv-ce-course/build.py
   ```

3. Commit **all three** generated files: `frontend/pharmacovigilance-ce-course.html`, `frontend/api/course-key.json` and `frontend/api/course-content.json`.
   If the answer key isn't updated, learners' correct answers to new or changed questions are marked wrong.

The build applies exact find-and-replace steps to the source. If the source has changed so that a step no
longer matches, it stops with `expected 1 match(es), found 0: '…'`. Update that step in `build.py` to match the new
source. Don't remove it.

Changing questions after people have started: learners keep the scores already recorded. Changing the **number** of
modules changes what "all knowledge checks complete" means, so check the register before doing that.

## Paid access

- **Price:** ₦19,999, paid once, for lifetime access. Payments are non-refundable (stated in the course terms at `#terms`).
- **Free preview:** the overview and Module 1. Every other module, the final assessment and the certificate need access.
- **Access types** (`course_learners.access`):
  - `paid`: paid through Paystack.
  - `sponsored`: added by MedNova, or used a partner code.
  - `early`: enrolled before payments started.
  - Empty: free preview only.
- **Course content:** module content and quizzes are in `frontend/api/course-content.json`, generated by `build.py`. The server sends them module by module, only to learners with access. The page itself holds just the course outline.
- **Payments switch:** `COURSE_REQUIRE_PAYMENT` must be `true` for payments to be required. Until then, everyone has the full course. The sponsored learners and partner codes you add still work, and keep working once payments are switched on.

### Admin (in the register, `#register`)
- **Add sponsored learners:** paste `Full name, email` lines and enter a sponsor name. Their course unlocks when they sign in with that email. They can optionally get an invitation email.
- **Partner codes:** set a sponsor, a number of places and an optional expiry. Codes are generated as `SPONSOR-XXXXXX`, or you can set your own. Learners enter the code on the enrol page. You can switch a code off at any time.
- **Remove access:** for mistakes. The learner's progress and certificate are kept.
- **Register:** shows each learner's access type, sponsor, payment reference and partner code. All of these are included in the CSV.

### Paystack
- **Payment flow:** the server creates the payment and sends the learner to Paystack's checkout page. Paystack returns them to `/pharmacovigilance-ce-course?reference=…`, and the server checks the payment with Paystack before unlocking the course.
- **Webhook:** Paystack also calls `/api/course?action=paystack-webhook`, so access is granted even if the learner closes the tab after paying. The webhook's content is never trusted: every reference is re-checked with Paystack.
- **Records:** every attempt is stored in `course_payments` (reference, amount in kobo, status). Partner codes are in `course_codes`. A partner code is redeemed by the `redeem_course_code` database function, which caps attempts at 10 wrong codes per learner per day.

### Going live with payments
1. In the Paystack dashboard, go to **Settings → API Keys & Webhooks**:
   - Copy the **secret key**. Use the test key first, then the live key.
   - Set the **webhook URL** to `https://mednovalife.com/api/course?action=paystack-webhook`.
2. In Vercel, under **Settings → Environment Variables**, for Production:
   - Add `PAYSTACK_SECRET_KEY`.
   - Add `COURSE_REQUIRE_PAYMENT` = `true`.
   - Redeploy.
3. With the test key, pay with Paystack's test card (`4084 0840 8408 4081`, any future expiry date, CVV `408`, PIN `0000`, OTP `123456`), then check that the course unlocks.
4. Swap in the live secret key and redeploy.

## Pass marks, unlock order and the final assessment wait

- Each knowledge check is passed at 60% (3 of 5, 5 of 8). The best score counts, and learners can retake checks
  straight away. Module N unlocks only when Module N−1 is passed.
- The final assessment unlocks when all knowledge checks are passed. It is marked only by the server: its answer
  hashes are left out of the page, and learners see only their total score. Pass mark 80%.
- A failed final assessment locks it for 24 hours (`results.final.retryAt`). After passing there are no retakes.
- The server (`frontend/api/course.js`: `MODULE_PASS_PCT`, `FINAL_WAIT_MS`) enforces all of this. The page
  (`MODULE_PASS_PCT`, `FINAL_WAIT_HOURS`, set in `build.py`) only displays it, so change both together.
- To let a learner retake the final assessment early, remove `retryAt` from `results.final` on their row in Supabase.

## Signature on certificates

Certificates show the signatory's name in script lettering. To use a real signature, save a scan as a PNG with a
transparent (or white) background at `frontend/public/images/course/signature.png` and deploy. About 1200 × 400 px,
cropped tight to the ink, works well. No rebuild is needed: certificates pick it up the next time they are drawn,
including certificates issued earlier.

## Certificates

Certificates are issued only by the server, by the `issue_course_certificate` database function, once all knowledge
checks are complete and the final assessment is passed. Number format: `PVCE-<year>-<serial>-<check code>`, for
example `PVCE-2026-00001-K7QM`. The serial comes from the `course_cert_serial_seq` sequence, and the 4-character check
code is random so numbers can't be guessed. The number, printed name (`cert_name`), date (`earned_at`) and score
(`cert_final_score`) never change after issue. To correct a misspelled name on an issued certificate, update
`cert_name` in Supabase.

Lookup for a verification tool: `GET /api/course?action=verify&id=PVCE-2026-00001-K7QM` returns
`{ valid, certId, name, earnedAt, finalScore, course }`. The public page is `/pharmacovigilance-ce-course#verify`.

## Analytics events (Google Analytics G-70L73W3SD6)

`course_sign_in`, `course_device_confirmed`, `course_module_complete` (module_number, score, total),
`course_final_assessment` (score_percent, passed), `course_certificate_issued` (score_percent). No names, emails
or certificate numbers are sent.
